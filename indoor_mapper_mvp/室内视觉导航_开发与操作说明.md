# 室内视觉导航模块：开发与操作说明

## 当前交付状态

已在现有程序之后增加独立视觉导航模块，继续复用原有建模和照片定位功能。现有模型、数据库和 site_map.json 不需要改动。手机页面已增加实景导航入口；Windows 主窗口增加“实景导航设置”入口，重新打开桌面程序后可见。

现有真实场景不是商场，未创建虚构的“C区奶茶店”。程序为当前模型准备了8个候选导航点，采用视频中真实注册相机的站位和用户已写的区域名称。初始通路保留视频相邻相机轨迹的折线，不将转角直接切成一条直线。通路是否仍可通行、参考图是否对应合适的路口，需要现场核对。配置中的 field_verified 默认 false，手机据此标记为路线预览。

当前模型尺度仍为 COLMAP 任意单位。程序不把这些数值写成“米”。补录两个相机站位之间的实测直线距离后，才会显示米制距离。一条标尺只确定整体尺度，不能修复模型漂移或错误的几何重建。

## 先前代码的接入分析

自动建模位于 mapper/engine.py 的 reconstruct，照片定位位于同文件的 localize。每次定位独立写入项目 queries/时间编号/result.json。成功结果的 pose 包含 xyz（长度3）、forward_world（长度3）、rotation_camera_to_world（3乘3）以及 model_id、model_signature。只有 status=success 的结果允许启动或更新导航。

相机坐标为 X向右、Y向下、Z向前；世界朝向 forward_world 等于相机到世界旋转矩阵的第三列。世界 XYZ 不是东、北、上，也没有默认米制尺度。导航用 world_up 指定世界上方向，当前从此前已保存的朝向标定中读取。左右转使用水平投影后的向量叉积和点积计算，不依赖节点名称或底图左右方向。

接入点是定位完成后的 result.json 或返回结果对象。mobile_server.py 保留原定位流程，完成后在服务端记录这个真实结果；新增导航接口只接受任务编号，不接受手机任意提交一组三维坐标。桌面和其他程序也可以直接调用 NavigationController.start(result, destination)，随后调用 update(session_id, new_result)。

原底图可能仍显示估计位置，因为此前平面标定尚未完成可靠校正。新模块使用原始三维坐标中的独立导航图，不把估计底图像素用于路线计算。这两种状态并不相同。

## 文件结构

| 文件 | 作用 |
| --- | --- |
| mapper/visual_nav/graph.py | NavigationGraph、模型指纹检查、通路吸附、数据校验 |
| mapper/visual_nav/poi.py | POIManager、名称与中英文别名解析、歧义拒绝 |
| mapper/visual_nav/planner.py | RoutePlanner、A*、单向及关闭通路处理 |
| mapper/visual_nav/instructions.py | NavigationInstructionGenerator、向量转角、楼层变化指令 |
| mapper/visual_nav/reference.py | ReferenceImageManager、参考图与真实拍摄位姿选择 |
| mapper/visual_nav/renderer.py | ArrowOverlayRenderer、独立的参考图箭头绘制接口 |
| mapper/visual_nav/controller.py | NavigationController、会话、重新定位、偏离重算、到达和暂停 |
| mapper/visual_nav/authoring.py | 从注册帧生成候选节点、维护和备份独立配置 |
| mobile/navigation.js 与 navigation.css | 手机实景导航界面 |
| mobile/navigation-admin.html 与 navigation-admin.js | 电脑本机的节点、连接、POI和距离标尺维护 |
| navigation_cli.py | 读取已有 result.json 的命令行入口 |
| tests/test_visual_navigation.py | 路径、转向、失败、重新定位、楼层与箭头测试 |

各项目新增 visual_navigation.json。导航点包含 node_id、name、region、xyz、floor、type、references；连接由 edges 的 from/to 定义，同时支持 bidirectional、enabled、kind 和 polyline。每张 reference 包含真实图片路径、相机 xyz、forward_world、rotation_camera_to_world 和 camera 内参。POI 的 node_id 绑定目的节点，aliases 保存别名。

导航结果和叠加图片写入 navigation_runs/导航会话/版本/，其中 route.json 保存起点、终点、折线、模型单位与可选米制距离、角度、操作、参考照片信息和路线步骤。该目录与导航配置备份均位于项目内部，不修改现有定位结果。

## 第一次使用：电脑配置

1. 启动“启动手机端.cmd”。服务必须指向要使用的地图项目。
2. 在电脑浏览器打开 http://127.0.0.1:8765/navigation-admin.html，后面保留完整的 ?token= 访问码。也可以从桌面程序“实景导航设置”进入。此设置页面仅允许电脑本机访问。
3. 检查候选8个节点。逐一查看参考照片，核对当时手机的实际站位；画面中出现一扇门不代表手机就站在门口。选择合适的帧，再填写名称、区域、楼层与别名。可以添加或移除节点。
4. 检查连接，删除隔墙连接或不可通行连接。需要返回时勾选“双向”，仅单向通行时取消。跨楼层的连接必须标为楼梯、电梯或扶梯。
5. 测量两处站位之间的实际直线距离，选择两节点并输入米数。不能用绕过拐角后的行走长度替代直线距离。留空会保持现有标尺。
6. 核实后才勾选“已核实节点站位、楼层和通路”，保存。旧版导航配置会自动备份，正在进行的导航需要重新开始。

第一版节点直接绑定注册相机站位，因此相机高度应尽量与建图时一致。节点的XYZ是该相机站位，并非程序自动识别出的地面点。如果需要非常窄的通道，应精确维护中心线和吸附半径；默认半径只为候选数据提供起始值，不能保证识别所有墙体。

## 手机使用

1. 在同一 Wi-Fi 下打开完整手机链接，刷新获取新界面。
2. 使用原有“拍照定位”或相册选择完成定位。
3. 在“实景照片导航”中选择目的地，或输入“我要去某地点”，点击“开始导航”。名称和别名在电脑维护，不调用大型语言模型。重名时要求补充区域，不猜测目的地。
4. 界面突出显示目的地、你当前应执行的操作、剩余步骤、距离和真实参考图。当前没有标米时明确提示，不编造米数。
5. 按现场环境行走，到下一处导航点后点击“我已移动，拍照更新导航”。照片继续进入原来的 COLMAP 定位流程。模块读取新的真实位置，重新计算剩余路线；偏离原路线且位于另一条已标通路时重新规划。
6. 新照片失败或不在已标通路附近时暂停导航，隐藏旧箭头，不用上一次坐标假装定位成功。可以重拍；如果确实走到了未覆盖通路，需要维护者补充节点和连接。
7. 到目的节点附近，还须成功定位并通过距离和连通性检查才显示到达。提前预览最后一张图不会触发实际到达。

“上一张/下一张参考图”只预览路线，不改变当前位置。历史定位记录始终标为回放。不能将历史回放当成新一轮现场步行测试。

## 箭头的含义与第一版范围

本版在真实参考照片上绘制具有收缩和透视感的醒目箭头。它是方向示意，不是实时摄像头AR，也没有把未测量的地面宣称为真实地面。renderer 独立于路线规划；接口保留基于已测地面和相机内参的三维投影能力，后续可以接实时相机和已确认地面几何。

参考图片可能与用户当前拍照方向不同。用户操作根据最新手机朝向计算；图中的箭头根据参考图片自己的拍摄朝向计算。因此若两者不同，界面会明确说明“图中显示什么，你当前该做什么”。应优先为关键路口保存接近到达方向的参考照片，减少这种视角差异。模板会一并保存同站位附近的多个真实视角，选图优先匹配进入该步骤的方向。

程序不能仅凭一张照片判断墙后通行情况，也不自动识别地图里未标注的楼梯、电梯或店铺。导航依赖维护好的通路图、定位的几何质量和现场核对。

## 接口与命令行

新增接口为 GET /api/navigation/catalog，POST /api/navigation/start（job_id、destination），POST /api/navigation/update（id、job_id），GET /api/navigation/session?id=，以及导航图片接口。导航设置 GET/POST /api/navigation/config 仅在回环地址开放。这些接口继续使用原来的访问码。

```powershell
.venv\Scripts\python.exe navigation_cli.py --project projects/map_20261011_035045 --bootstrap
.venv\Scripts\python.exe navigation_cli.py --project projects/map_20261011_035045 --result projects/map_20261011_035045/queries/20261011_061014_cf4924/result.json --destination 参考点1
```

第二条命令是明确标记的历史结果回放，不会启动建模或重新定位。项目名和定位记录可能变化，必要时替换路径。没有增加新的 Python 依赖，继续使用原有 NumPy、Pillow 和 COLMAP 环境。

## 验证与必须手动完成的事项

已运行现有及新增单元测试，验证A*、真实3D距离、任意尺度、名称别名、左右转/掉头、单向和封闭连接、跨楼层连接、过远或歧义吸附、失败暂停、偏离重算和到达判定。还通过正在运行的 HTTP 接口，将已保存的一张真实照片重新提交原有 COLMAP 流程，得到成功定位后自动生成7步实景导航。这是实际照片的程序链路测试，不是现场步行验收。

你仍需亲自完成：核对8个站位和通路；输入一段实测距离；携带手机从起点走到终点并在关键点重拍。没有现场人员、手机控制与空间事实时，不能声称已经完成物理步行测试。

建议验收记录包括：起点照片及定位编号、每次重拍的结果编号、目的地、指令方向是否正确、参考照片是否容易对应现场、剩余距离是否合理、走错分支是否重算、失败时是否暂停、最终到达是否与现场一致。优先选一段短且连续的真实走廊，先确认单楼层流程，再扩展楼梯和电梯。


最终回归结果：39项 Python 测试通过；JavaScript 语法检查、应用缓存隔离检查通过。已重新执行真实照片定位并生成7步导航；尚未完成持手机现场步行测试。

当前步骤优先在本次成功定位的原始照片上叠加箭头，照片视角与本次手机朝向一致。后续步骤调用预存参考图。如果没有可用的本次照片，则回退到预存参考图并标明视角差异。已对真实照片验证当前操作和图中方向一致。


## 导航接入失败修复

上一版候选图只取了视频前80张注册帧，同时将拍摄高度变化混入通道偏离距离，导致已定位成功却无法开始导航。本次已改为覆盖完整注册视频，旧项目通过保留现有标注的扩展函数补齐后续轨迹；已有节点名称、POI别名和标尺不被覆盖，扩展前自动备份。当前项目由8点补全为13点，包含全部141张注册帧到frame_000155的候选轨迹。新增通路仍需现场核实。

普通步行通道改为分别检查水平偏离与高度差；楼梯、电梯等连接保留三维检查。路线距离仍使用原始三维坐标计算，不将未标米的模型单位显示为米。电脑设置新增水平范围和高度容差，并提供“补全视频后续轨迹”按钮。

手机会显示独立导航覆盖图、真实照片位置、水平偏离和高度差。上方底图中的旧通路与此图是两套数据，底图上看起来靠近通道不代表三维导航图已经覆盖。

若仍无法自动接入，界面展示附近最多3张参考站位照片。只有你认得对应的拍摄站位、确认可从当前位置直接步行到达时，才选择照片并勾选确认，然后点击“按我确认的通路开始导航”。必须先选择目的地。程序为本次真实位置到该节点建立由用户确认的临时连接，原坐标保持不变；不会保存成全局吸附规则，也不会在下一次拍照后自动复用这次确认。过远、高度不符或没有连接的点仍会拒绝。

此确认并不让程序自动识别墙体。若参考照片不认识、有墙或门禁阻隔、附近没有候选点，请在电脑补充真实节点和通路。没有必要连续重拍同一站位来掩盖导航图缺失。

修复后44项测试通过。对本次几条真实定位记录复测：原本被高度误差拒绝的位置、C室走廊及后半段位置已能自动规划；最新偏离轨迹的站位会提供两个候选接入点，明确确认后可正常规划，原始定位坐标未变。
