# 最小可行开发方案

目标是在 Windows 上完成真实视频建图、照片定位和三维显示，先跑通本地流程。

1. 检查环境。复用已安装的 COLMAP 4.2.1 CUDA，使用 Python 3.12 独立虚拟环境。FFmpeg 随 imageio-ffmpeg 安装，Open3D 负责交互显示。
2. 建图。读取 MP4/MOV 元数据，按时间段抽取候选帧，每段保留较清晰的画面，并过滤极模糊、近乎重复的画面。COLMAP 提取 SIFT、全量匹配、执行增量 SfM。保存原图、数据库、二进制模型、文本参数、PLY 点云及日志。
3. 定位。复制地图数据库，对独立照片提取特征，只计算照片与参考图的匹配。复用 image_registrator 的二维到三维注册，禁用无结构回退，不进行改变整张地图坐标的全局优化。读取真实位姿并独立检查对应数量、正深度和重投影误差。失败时输出诊断，没有位姿字段。
4. 显示。Tkinter 提供本地中文控制窗口，Open3D 在独立进程显示点云、参考相机和查询相机。多个地图组件分别显示，定位匹配到哪个组件就使用哪个组件的坐标系。
5. 验证。运行坐标转换单元测试；用现有真实视频进行端到端建图；用不参与建图的视频帧进行流程测试，并尝试此前拍摄的独立照片；用白图或不相关画面测试失败行为；创建并渲染三维窗口。最后由用户另拍走廊视频与新照片进行现场验收。

MVP 默认最多400帧，适合一段短走廊，不承担大范围实时定位。SIFT 和 COLMAP 使用成熟算法，无模型训练。本阶段不做稠密网格、手机端 AR、导航路径规划或 hloc 集成。单目重建没有已知物理尺度，输出 XYZ 使用地图任意尺度；后续可通过已测距离进行尺度标定。

官方依据：https://colmap.github.io/faq.html#register-localize-new-images-into-an-existing-reconstruction
