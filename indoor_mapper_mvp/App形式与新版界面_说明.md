# 寻位 App 形式与新版界面

## 本次需求转译

在现有 Windows 室内三维重建与视觉定位程序上，选择适合 Hackathon、可复用现有引擎的手机 App 方案。保留拍照或选图、地图、照片位置、拍摄方向、重要地点和已标路线。界面应清晰、克制，同时通过字体、色彩和几何布局体现简洁优雅的后现代气质。完成实现和测试，说明真正可用的功能、安装条件与用户必须手动完成的操作。

## 选择的方案

采用渐进式网页应用 PWA。手机负责拍照、上传和展示，Windows 电脑负责 COLMAP 定位。用户无需在手机上安装 Python 或 COLMAP，也无需重新建立已有地图。现有网页仍可使用，在满足浏览器安装条件后，可获得桌面图标和独立窗口。

本次已加入应用清单、192/512 图标、独立窗口声明、安装事件处理、安装说明和应用外壳缓存。添加桌面入口后，应用从根地址启动；访问码在首次成功连接时保存在本浏览器本地。若系统将安装应用放入不同的存储环境，或用户清理过数据，需要先用完整手机链接打开一次。

这不是安卓 APK 或 iOS 原生安装包。当前电脑没有检测到 Android SDK，本次没有声称生成可安装的 APK。后续如需要应用商店分发或严格控制摄像头镜头，可以沿用本页面与接口制作原生客户端。需要额外处理构建、签名、相机权限和平台适配。原生外壳本身不会提高定位准确度。

## 现在怎样使用

保持 Windows 手机服务运行，手机与电脑连接同一 Wi-Fi，打开电脑显示的完整链接。刷新页面即可使用本次新界面，拍照功能与原来的定位流程一致。

点击顶部 App 按钮查看添加桌面入口的说明。Android 建议通过 Chrome 或 Edge 的菜单操作，iPhone 通过 Safari 分享菜单操作。微信内页面先转到系统浏览器。浏览器是否提供安装或快捷方式选项，取决于设备和连接方式。

目前的 192.168.*.* 地址使用 HTTP。手机不能将电脑的局域网地址当作自己的 localhost。这个连接可以用于当前拍照上传流程，但不满足正式 PWA 安装所需的 HTTPS 条件。添加网页快捷方式与完整 PWA 安装是两件不同的事情；网页不会把未满足条件的按钮写成“已经安装”。

## 可信 HTTPS 与正式安装

程序已提供可选 HTTPS 参数：

```powershell
.venv\Scripts\python.exe mobile_server.py --port 8766 --cert certs\server.pem --key certs\server-key.pem
```

证书需要包含实际使用的电脑 IP 或域名，并被手机信任。以上命令要求用户已有相应证书文件，不会自动生成证书。可由学校或队友协助配置可信证书和设备信任。不要通过忽略浏览器安全警告来测试正式安装，也不要把证书私钥发给他人。certs 文件夹已从源码打包中排除。

本次没有修改手机证书、开放公网服务或设置公共隧道。当前服务器继续使用原来的 HTTP 地址。HTTPS 启动能力已实现，手机上正式安装仍待提供可信证书并实际验收。

只有浏览器触发可安装事件时，页面才提供“安装寻位”按钮。其他情况给出对应平台的操作说明。安装后电脑仍要运行，网络断开时只能查看应用界面与拍摄指南，不能产生定位结果；应用不会缓存用户照片、底图、位置结果或 API 响应来冒充实时定位。

## 视觉设计

采用暖白底色、墨色文字与少量蓝色、灰粉色和黄绿色细节。标题使用本机中文衬线字体，操作文字保持易读的无衬线字体。品牌符号为几何化的相机位置与指向，不依赖外部图片或在线字体。地图占据主要空间，少量不对称圆角与细线给界面层次。地点改为简洁的列表式布局，减少大面积重复卡片。

红色箭头、橙色估计位置和标定状态仍有清晰语义。估计位置不会用于生成精确出发路线；真实定位失败时不会显示伪造坐标。

## 手动操作与验收

1. 手机重新打开完整链接，确认地图和地点出现。
2. 从 App 说明进入系统浏览器，尝试添加桌面快捷方式。正式安装需先满足可信 HTTPS 条件。
3. 使用真实环境照片定位，核对区域、地图位置和拍摄方向。
4. 确认证书信任或系统相机权限需要用户本人在手机上操作。
