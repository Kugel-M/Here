# 室内三维重建与视觉定位 MVP

本程序在 Windows 本机处理手机视频和照片。视频建图使用 FFmpeg、COLMAP SfM；新照片定位复用 COLMAP 图像注册；三维显示使用 Open3D。没有模型训练，也没有云端上传。

## 在这台电脑上启动

环境已经安装完成。双击同目录的 **启动程序.cmd**，即可打开中文窗口。不要点击系统 `python.exe`，它目前指向 Windows 应用商店别名。

项目目录为 `C:\Users\24237\Desktop\Hackathon\indoor_mapper_mvp`。程序会记住上次打开的地图。代码、运行环境和已有测试地图都保存在这里，原视频和以前的 COLMAP 结果没有覆盖。

## 第一次使用

1. 点击“检查环境”，确认日志中 COLMAP、FFmpeg 路径有效，Open3D 已安装。这台电脑已确认使用 Python 3.12、RTX 5060 Laptop GPU、COLMAP 4.2.1 CUDA 和 FFmpeg 7.1。
2. 在“建图视频”选择 MP4 或 MOV。建议使用手机原始文件，保持同一个1倍镜头，不在视频中切换焦段。对一段短走廊可先用每秒2帧、上限400帧；转弯较多可以改为每秒4帧。
3. 点击“开始建图”。程序先按目标频率的两倍抽取候选帧，每个时间段优先保留较清晰的一帧，排除极模糊和近乎重复的画面，然后提取特征、匹配、重建。频率会随视频时长和帧数上限调整。界面显示当前阶段与运行日志，不能据此估算固定完成时间。
4. 建图完成后，项目会自动加载。点击“查看三维场景”可查看最大的地图组件。若有多个模型，在“定位模型”选择具体编号后再查看；`auto` 表示定位时尝试各组件。
5. 在同一走廊另一个位置拍摄一张新的 JPG、JPEG、PNG、BMP 或 TIFF 照片，选择为“定位照片”。HEIC 请先通过手机导出为 JPG。
6. 点击“开始定位”。成功后切换到“用户地图与参考画面”，展示查询照片和匹配参考图。完成区域命名及平面图标定后，可看到区域名称、地图位置和朝向。原始 XYZ 与完整位姿保留在“技术日志与原始坐标”。点击“查看三维场景”可打开 Open3D：蓝色相机线框为建图视角，红色线框和球体为新照片相机；红色线框中心向前伸出的线段表示拍摄方向。定位相机旁的红、绿、蓝轴分别对应相机 X、Y、Z 轴。
7. 三维窗口中，左键拖动旋转、滚轮缩放、Ctrl+左键拖动平移。按 F 聚焦定位相机，按 R 恢复全景。关闭三维窗口不会关闭控制窗口。

新增的底图标定、区域命名和路线操作见同目录《地图标定与导航_操作说明.md》。已有地图与定位结果兼容，无需重新建图；主窗口增加“打开定位结果”按钮，重新打开项目时也会尝试加载最近一次结果。

建图失败后，旧输出与日志会保留。修正拍摄数据或设置，再点击“开始建图”会创建新的项目。GPU 报错时可取消“使用 NVIDIA GPU”，再运行。点击“取消当前处理”会终止当前外部进程；被中断的地图不会标记为可用地图。

## 定位失败时

失败结果会逐个列出模型诊断，保存于查询目录的 `result.json`，界面也显示原因。

| 显示原因 | 含义与处理方法 |
| --- | --- |
| 特征不足30个 | 照片可能模糊、过曝或主要拍到白墙。把门框、标牌、固定家具拍进画面。 |
| 没有通过几何验证的匹配 | 照片可能不在地图覆盖区域，或视角、光照差异较大。靠近建图路线、保持相似镜头再拍。 |
| 有二维匹配，但未通过 PnP 注册 | 二维相似不等于可靠三维定位。可能缺少可用三维点或几何分布不佳，应补充有移动视差的建图画面。 |
| 候选位姿未通过独立质量检查 | 对应数量、正深度比例或重投影误差不合格。程序拒绝展示该位置。 |
| 多个模型定位支持相近 | 无法唯一确定组件。根据已知拍摄区域选择具体模型后重试。 |
| 外部命令失败 | 查看提示的日志文件。检查 COLMAP 路径、GPU、磁盘空间及文件权限。 |

不要通过不断降低阈值来获得看似成功的坐标。本程序要求至少30个有效二维到三维对应、至少95%的正深度，以及中位数不超过4像素、90分位不超过12像素的重投影误差。这些是 MVP 的拒绝条件，不代表对现场正确性的保证。

## 坐标与地图的含义

XYZ 表示相机光心在模型自身坐标系中的位置，不是 GPS，也不是已标定的米。单目 SfM 的位置、整体朝向和尺度没有自动对齐真实建筑，后续可通过已测距离与控制点进行标定。

6DoF 结果包括 XYZ、相机到世界的3×3旋转矩阵、COLMAP 世界到相机的四元数和4×4相机到世界变换。COLMAP 外参 `t` 不是相机位置；程序用 `C = -R.T @ t` 计算光心。相机坐标轴为 X向右、Y向下、Z向前。

每个独立模型都有自己的坐标系，不能直接合并其 XYZ。自动定位会尝试多个模型，但展示时只使用成功定位的那个模型。程序保存的是稀疏点云，不是带贴图的建筑实体；白墙等缺少纹理的区域可能没有点。

定位时会复制地图数据库并创建独立查询目录，保留原地图。新照片有独立相机内参，不会强行套用视频镜头参数。注册使用实际三维点对应，不启用无结构回退，不进行会改变整张地图坐标的全局束调整，并检查原参考相机位姿保持不变。低纹理、镜面、重复门窗、移动人群或原地旋转仍可能让建图或定位失败。

## 导入以前的 COLMAP 结果

点击“导入旧 COLMAP 结果”，选择包含 `images`、`database.db` 和 `sparse` 的目录。数据库与模型也可以位于 `processing` 或 `processing_日期` 子目录。若有多份处理结果，请直接选择具体的处理子目录，程序会寻找其上一级的 `images`。

导入会复制模型和数据库及模型引用的原图，生成独立项目。请先停止旧数据库的写入。必须提供与模型对应的数据库，不能只给 PLY 点云；PLY 没有定位所需的参考特征和二维到三维索引。当前匹配列表要求参考图文件名不含空格，本程序生成的帧名符合要求。

## 更换电脑或重装环境

需要 Windows 10/11、Python 3.12 64位和 COLMAP 4.2 CUDA版。没有 NVIDIA 显卡时可使用对应 COLMAP 版本及 CPU 模式。Open3D 交互窗口还需要可用的图形驱动。

在新电脑安装 Python 3.12 和 COLMAP，解压项目源码，然后修改 `config.json` 的 `colmap_exe` 为实际 `colmap.exe` 路径。空的 `ffmpeg_exe` 表示使用随依赖安装的 FFmpeg。

在项目目录打开 PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

脚本创建独立 `.venv` 并安装依赖，不修改系统 Python。`requirements.txt` 为直接依赖，`requirements-lock.txt` 为本次实际环境的完整版本清单。安装完成后双击启动脚本。源码压缩包不包含 `.venv`、COLMAP 可执行文件和用户拍摄数据；下载依赖需要网络。

## 命令行和测试

普通使用无需输入这些命令。开发或排错时可以在项目目录运行：

```powershell
$env:PYTHONUTF8='1'
& .\.venv\Scripts\python.exe app.py doctor
& .\.venv\Scripts\python.exe app.py reconstruct --video 'D:\你的走廊.mp4' --project 'projects\new_map' --fps 2
& .\.venv\Scripts\python.exe app.py localize --project 'projects\new_map' --photo 'D:\你的新照片.jpg'
& .\.venv\Scripts\python.exe app.py view --project 'projects\new_map' --model 0
& .\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

成功返回0，未通过定位返回2，运行异常返回1。定位失败的 JSON 不包含 `pose` 字段。命令行 `--cpu` 可用于建图与定位。需要展示定位标记时，在 `view` 命令增加 `--result '查询目录\result.json'`，模型编号应与该结果一致。

## 你需要手动完成的现场验收

拍摄一段新走廊视频，以缓慢行走为主，保持镜头和焦段固定；转角时让前后区域的固定物体共同出现在画面中。使用原始文件，避免聊天软件压缩。然后在该走廊另一位置重新拍摄照片，不能把建图帧截图作为最终验收照片。

在窗口中完成建图、定位与查看标记，核对相机位置是否位于合理区域、方向是否指向实际拍摄目标。若要验证米级误差，还需要量取参考距离、标定尺度并测量拍照位置。程序已实现自动尝试定位，但目前没有完成这组新走廊数据的现场验收。

实现依据：[COLMAP 新图像注册文档](https://colmap.github.io/faq.html#register-localize-new-images-into-an-existing-reconstruction)。
